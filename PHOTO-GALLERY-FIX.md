# VÉLOCITY Collection photograph repair (2026-11-15)

The Collection gallery is generated by `static/js/vehicle-gallery.js`, NOT `static/js/cars.js`.

## Changes
- Accept CarVariables image URLs from its website or CDN, including legitimate query strings and relative `/images/` URLs.
- Prefer the local cached `/api/velocity/photo?file=...` endpoint, then try the provider URL if the proxy fails.
- Add console warnings for missing or unrecognized provider image URLs.
- Bump gallery JavaScript asset version in Collection, Discovery and Compare templates to prevent stale browser caching.
- Preserve the Collection video hero; image selection remains exclusive to Compare.

## Install (patch)
Copy patch files to your current VÉLOCITY project, keeping the folder paths. Restart `go run .` and refresh Firefox using Ctrl+Shift+R.

## Verify
1. In Firefox DevTools > Network, filter by `photo` or `avif`, reload `/cars`.
2. Verify `/api/velocity/vehicles?per=1&variants=1` responds with `success: true` and a result with `image_url`.
3. Test the filename from that result via `/api/velocity/photo?file=<filename>`. A 200 with `Content-Type: image/avif` is ideal.
4. If cards still show unavailable, inspect the console warning and image requests: 404/403/429/502 from the provider need a separate backend/provider fix.

No API keys are included in the archive. Configure `CARVARIABLES_API_KEY` in the terminal that starts `go run .`.
